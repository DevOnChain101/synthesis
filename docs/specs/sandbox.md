# Sandbox on WSL (draft)

Scope: the Linux engine (`synt run`, `synt engine --stdio`, the desktop TUI tab through WSL2) when it detects it runs inside WSL. Code: `crates/synthesis-platform/src/wsl.rs` (detection, PATH scrub), `crates/synthesis-sandbox/src/{wsl,linux}.rs` (controls), `crates/synthesis-sandbox/src/bin/synthesis-sandbox-exec.rs` (seccomp), `crates/synthesis-terminal` (mode, preflight), `crates/synthesis-app` (`resolve_sandbox_mode`, MCP plan, `synt doctor`). Owner decisions: WSL is NOT isolation, so the sandbox blocks interop itself (users are not asked to edit `/etc/wsl.conf`); `synt doctor` only warns; fail closed.

**Interop closure is NOT proven until `cargo test -p synthesis-sandbox --test wsl -- --ignored` has passed on a real WSL2 distro.** Everything below was written and unit-tested without WSL; the Linux bubblewrap and seccomp tests run in CI (ubuntu), not on WSL.

## Threat
From inside WSL a command can start Windows programs (`cmd.exe`, `powershell.exe`) through the `WSLInterop` binfmt entry and the socket named by `WSL_INTEROP` (`/run/WSL/<pid>_interop`), find them on a `PATH` WSL extends with `/mnt/c/...`, talk to the Windows host over AF_VSOCK, use the WSLg sockets (`/mnt/wslg`), and read and write every Windows drive under `/mnt/*` (drvfs / 9p).

## Detection
`WslHost::probe(&Probe)` with injected `read`, `exists`, `env_set`. WSL if ANY positive signal: kernel strings say "microsoft" (WSL1/WSL2 told apart by "wsl2"), the `WSLInterop` or `WSLInterop-late` binfmt entry, `/run/WSL`, `/mnt/wsl`, `WSL_INTEROP` or `WSL_DISTRO_NAME` in the environment. Absence never means "not WSL". With no kernel word the version is `Unknown` (doctor warns). Once seen in a process it stays WSL. If `/proc/mounts` cannot be read (or WSL was only remembered), the drives are unknown: commands are refused, not run with drives visible. Interop counts as enabled if either binfmt entry says enabled; disabled only when binfmt_misc is readable and neither does. `WslHost::current()` re-reads `/proc/mounts` on every call (no stale cache); drives = `/mnt/*` plus `drvfs` / `9p aname=drvfs` mounts (not other 9p mounts such as `/usr/lib/wsl`).

## Effective mode
`resolve_sandbox_mode` (behind `Common::sandbox_mode()`, also used by the desktop) returns Enforce for best-effort, explicit or defaulted, on WSL. Preflight, notices, browser and exposure warnings all read that one value; `TerminalRuntime` repeats the rule for embedders. Only an explicit `off` runs commands unconfined, with a loud notice and a one-time stderr warning. A command the person types with `!` still runs unconfined (stderr warning once on WSL).

## Controls

| Control | Mechanism | Covers | Does not cover |
|---|---|---|---|
| Env | `scrub_env` in `build_env` (every backend, every command the terminal runtime starts: Bash, hooks, `!` is unconfined and not covered) and `Env::child_env` (every child that takes its env from it: MCP stdio, git helpers, browser worker, tools) | `WSL*`, `XDG_RUNTIME_DIR`, `WAYLAND_DISPLAY`, `DISPLAY`, `PULSE_SERVER` removed; each `PATH` entry canonicalised and the canonical path kept; relative / unresolvable / Windows entries dropped | Not a boundary: a program that knows an absolute path can try it |
| Interop socket | bubblewrap `--tmpfs /run` | `/run/WSL`, the socket, `/var/run` do not exist inside | A process started outside the sandbox, or one holding the fd |
| WSLg and `/mnt/wsl` | bubblewrap `--tmpfs /mnt/wsl`, `--tmpfs /mnt/wslg` (when present); a `resolv.conf` that is a symlink into `/mnt/wsl` is bound back read-only so DNS works | WSLg sockets, other distros' mounts | Nothing under them is reachable |
| AF_VSOCK, io_uring, x32 | seccomp filters (`seccompiler`, no unsafe in our code) installed by `synthesis-sandbox-exec --no-vsock -- bwrap ...`, inherited by every descendant: `socket(AF_VSOCK)` fails with EPERM; `io_uring_setup/enter/register` fail with ENOSYS (IORING_OP_SOCKET, kernel >= 5.19, would create a vsock socket without the `socket` syscall); on x86_64 every syscall number >= 0x40000000 (the x32 ABI) fails with ENOSYS | The Windows host channel | Other io_uring-free paths to vsock are not known but not excluded. AF_NETLINK is deliberately NOT blocked: it cannot reach Windows and `ip` / glibc need it. 32-bit compat processes are killed by the filters' arch check. Architectures other than x86_64 / aarch64: commands refused. Helper missing or untrusted (see below): commands refused |
| Windows drives, reads | bubblewrap `--tmpfs` over every drvfs mount AND every existing `/mnt/<letter>` directory, and over `/usr/lib/wsl/drivers` (the Windows driver store, 9p `aname=drivers`; masked by default, GPU compute may need it: `hide_windows_drives=false` leaves it) (default; `synt.sandbox.wsl.hide_windows_drives`, user or managed settings only); the workspace and `--sandbox-read` roots on a drive are bound back (read-only for reads) | `/mnt/c/Users/*/.ssh` and every other Windows file | Costs: sibling projects on a drive and symlinks into `/mnt/c` are not visible; turn it off knowingly (drives then stay READABLE, read-only) |
| Windows drives, writes | `check_policy` (before the private temp dir is created) and the read-only root; mounts are read-only when drives are left visible | ANY writable root or temp dir that is on, or contains, a Windows drive is refused (`InvalidPolicy`, never degraded): `/`, `/mnt`, a drive, a mount point, `/mnt/wsl*`, a custom-mount ancestor, and also a deep project directory. **A workspace on a Windows drive is always refused today.** An allow-list of drive workspaces was removed: the standard policy always carries `.git/hooks`, `.synt`, `AGENTS.md` as protected paths and a bind mount cannot protect them on a drive (case-insensitive names, 8.3 aliases, trailing dots/spaces, NTFS streams), so every drive workspace would be refused anyway, and a deny-list of system directories would only invite bypasses. Move the project into `~/` | Roots are canonicalised once and the same paths go to the bind arguments |
| Backend | Landlock is refused on WSL (not in the chain; `wrap` errors) | Landlock cannot block `connect()` to a unix socket path | n/a |
| Helper trust | `helper_check`: `synthesis-sandbox-exec` next to `synt`, not a symlink, owned by root or the current user, not group/world-writable, same for its directory; the running binary must not be `(deleted)`; at wrap time a helper under any writable root is refused | A swapped helper would drop the seccomp filter | Installed through `scripts/install.sh` (fails on Linux without it), the release archive (smoke test runs `--no-vsock -- /bin/true`), npm and Homebrew. `cargo install` and a plain `cargo build -p synthesis-cli` do NOT build it: also run `cargo build -p synthesis-sandbox`; `synt doctor` says `sandbox helper missing or untrusted` |
| Fail closed | `BestEffort` is Enforce; no bubblewrap, no helper, unreadable `/proc/mounts`, WSL1 or a refused policy means commands are refused | | `--sandbox off` |
| Spawns outside the sandbox | An approved PROJECT stdio MCP server is refused on WSL with a reason; hooks run through the terminal runtime (sandboxed); user-owned MCP servers (user, local, synthesis scope) run unsandboxed with the scrubbed `Env::child_env`; the browser worker runs outside the OS sandbox with the scrubbed env (Chrome has its own sandbox) | | A user-owned MCP server and the browser worker can still use interop through an absolute path; so can the person's own `!` commands |

The binfmt entry cannot be removed without root: without the env var, the socket and a runnable path, executing a Windows binary fails, but the entry stays registered. A residual risk is that `/init` may find an interop socket by another route; unverified on a real WSL2.

## `synt doctor`
WSL rows, warnings only, with the exact `/etc/wsl.conf` line and `wsl --shutdown`: WSL1 / WSL2 / unknown; Windows interop (the kernel's state decides, `wsl.conf` only says what the next start does, an unreadable state is reported as unknown, `enabled=false # comment` is parsed); the number of Windows directories in `PATH` (a count, never the entries); automount root and options (information only); drives mounted read-write; bubblewrap works, Landlock ABI (not used); `synt` binary on `/mnt`. Names of variables only.

## Tests
Pure (all OSes): `synthesis-platform` `wsl::tests` (detection signals, mounts, PATH scrub with an injected canonicaliser, `wsl.conf`), `synthesis-sandbox` `wsl::tests` (env scrub, mount policy: `/`, `/mnt`, `/mnt/c/Users`, `/mnt/c/Users/u`, `/mnt/wsl/x/y`, custom-mount ancestor, system dirs, protected paths) and `linux::tests::bwrap_wsl_*` (arguments: masks incl. the driver store, hidden drives incl. unlisted `/mnt/<letter>`, resolv.conf, helper in front, unknown mounts refused, helper trust) and `linux::tests::x32_*` (BPF program), `synthesis-config` `env::tests`, `synthesis-terminal` `wsl_mode_tests`, `synthesis-app` (`resolve_sandbox_mode`, MCP plan, doctor). Linux, real bubblewrap (`linux::tests::real`): env and `/run` inside the sandbox, hidden drive, workspace writable, readable root bound back, `mountinfo` `ro` / `rw` flags of the bound mounts when the drive is left visible. `tests/wsl.rs`: the helper's seccomp filters (AF_VSOCK denied with EPERM, io_uring_setup ENOSYS, AF_UNIX / AF_INET work) and the whole chain `[helper, --no-vsock, --, bwrap, ...]` end to end. With `SYNT_REQUIRE_BWRAP=1` (set in the Linux CI jobs, which also relax the AppArmor userns restriction) a skipped bubblewrap test is a failure. Needs real WSL2: the `#[ignore]` test `real_wsl2_sandbox_closes_interop` (`cmd.exe` unreachable, no write to `/mnt/c`, AF_VSOCK denied).
