# Sandbox on WSL (draft)

Scope: the Linux engine (`synt run`, `synt engine --stdio`, the desktop TUI tab through WSL2) when it detects it runs inside WSL. Code: `crates/synthesis-platform/src/wsl.rs` (detection, PATH scrub), `crates/synthesis-sandbox/src/{wsl,linux}.rs` (controls), `crates/synthesis-sandbox/src/bin/synthesis-sandbox-exec.rs` (seccomp), `crates/synthesis-terminal` (mode, preflight), `crates/synthesis-app` (`resolve_sandbox_mode`, MCP plan, `synt doctor`). Owner decisions: WSL is NOT isolation, so the sandbox blocks interop itself (users are not asked to edit `/etc/wsl.conf`); `synt doctor` only warns; fail closed.

**Interop closure is NOT proven until `cargo test -p synthesis-sandbox --test wsl -- --ignored` has passed on a real WSL2 distro.** Everything below was written and unit-tested without WSL; the Linux bubblewrap and seccomp tests run in CI (ubuntu), not on WSL.

## Threat
From inside WSL a command can start Windows programs (`cmd.exe`, `powershell.exe`) through the `WSLInterop` binfmt entry and the socket named by `WSL_INTEROP` (`/run/WSL/<pid>_interop`), find them on a `PATH` WSL extends with `/mnt/c/...`, talk to the Windows host over AF_VSOCK, use the WSLg sockets (`/mnt/wslg`), and read and write every Windows drive under `/mnt/*` (drvfs / 9p).

## Detection
`WslHost::probe(&Probe)` with injected `read`, `exists`, `env_set`. WSL if ANY positive signal: kernel strings say "microsoft" (WSL1/WSL2 told apart by "wsl2"), the `WSLInterop` binfmt entry, `/run/WSL`, `/mnt/wsl`, `WSL_INTEROP` or `WSL_DISTRO_NAME` in the environment. Absence never means "not WSL". With no kernel word the version is `Unknown` (doctor warns). Once seen in a process it stays WSL. `WslHost::current()` re-reads `/proc/mounts` on every call (no stale cache); drives = `/mnt/*` plus `drvfs` / `9p aname=drvfs` mounts (not other 9p mounts such as `/usr/lib/wsl`).

## Effective mode
`resolve_sandbox_mode` (behind `Common::sandbox_mode()`, also used by the desktop) returns Enforce for best-effort, explicit or defaulted, on WSL. Preflight, notices, browser and exposure warnings all read that one value; `TerminalRuntime` repeats the rule for embedders. Only an explicit `off` runs commands unconfined, with a loud notice and a one-time stderr warning. A command the person types with `!` still runs unconfined (stderr warning once on WSL).

## Controls

| Control | Mechanism | Covers | Does not cover |
|---|---|---|---|
| Env | `scrub_env` in `build_env` (every backend, every command the terminal runtime starts: Bash, hooks, `!` is unconfined and not covered) and `Env::child_env` (every child that takes its env from it: MCP stdio, git helpers, browser worker, tools) | `WSL*`, `XDG_RUNTIME_DIR`, `WAYLAND_DISPLAY`, `DISPLAY`, `PULSE_SERVER` removed; each `PATH` entry canonicalised, relative / unresolvable / Windows entries dropped | Not a boundary: a program that knows an absolute path can try it |
| Interop socket | bubblewrap `--tmpfs /run` | `/run/WSL`, the socket, `/var/run` do not exist inside | A process started outside the sandbox, or one holding the fd |
| WSLg and `/mnt/wsl` | bubblewrap `--tmpfs /mnt/wsl`, `--tmpfs /mnt/wslg` (when present); a `resolv.conf` that is a symlink into `/mnt/wsl` is bound back read-only so DNS works | WSLg sockets, other distros' mounts | Nothing under them is reachable |
| AF_VSOCK | seccomp filter (`seccompiler`, no unsafe in our code) installed by `synthesis-sandbox-exec --no-vsock -- bwrap ...`; `socket(AF_VSOCK)` fails with EAFNOSUPPORT, inherited by every descendant | The Windows host channel | x32 ABI syscalls are not matched (stock WSL2 kernels do not enable x32; not verified). AF_NETLINK is deliberately NOT blocked: it cannot reach Windows and `ip` / glibc need it. 32-bit compat processes are killed by the filter's arch check. Architectures other than x86_64 / aarch64: commands refused. Missing helper: commands refused |
| Windows drives, reads | bubblewrap `--tmpfs` over every drvfs mount (default; `synt.sandbox.wsl.hide_windows_drives`, user or managed settings only); the workspace and `--sandbox-read` roots on a drive are bound back (read-only for reads) | `/mnt/c/Users/*/.ssh` and every other Windows file | Costs: sibling projects on a drive and symlinks into `/mnt/c` are not visible; turn it off knowingly (drives then stay READABLE, read-only) |
| Windows drives, writes | `check_policy` (before the private temp dir is created) and the read-only root | Refused: any writable root that is or contains `/`, `/mnt`, a drive or a mount point; `/mnt/wsl*`; fewer than 3 components below the drive (`/mnt/c/Users/u`); AppData, Windows, ProgramData, Program Files*, Recycle Bin, System Volume Information; a root that does not contain the cwd; a drive temp dir; `deny_paths` / `readonly_paths` inside a drive workspace (case-insensitive names and 8.3 aliases make a bind mount unable to protect `.git/hooks`: such a workspace is refused, move it into `~/`). Roots are canonicalised once and the same paths go to the bind arguments | A workspace deep on a drive that passes the checks is writable by design |
| Backend | Landlock is refused on WSL (not in the chain; `wrap` errors) | Landlock cannot block `connect()` to a unix socket path | n/a |
| Fail closed | `BestEffort` is Enforce; no bubblewrap, no helper, WSL1 or a refused policy means commands are refused | | `--sandbox off` |
| Spawns outside the sandbox | An approved PROJECT stdio MCP server is refused on WSL with a reason; hooks run through the terminal runtime (sandboxed); user-owned MCP servers (user, local, synthesis scope) run unsandboxed with the scrubbed `Env::child_env`; the browser worker runs outside the OS sandbox with the scrubbed env (Chrome has its own sandbox) | | A user-owned MCP server and the browser worker can still use interop through an absolute path; so can the person's own `!` commands |

The binfmt entry cannot be removed without root: without the env var, the socket and a runnable path, executing a Windows binary fails, but the entry stays registered. A residual risk is that `/init` may find an interop socket by another route; unverified on a real WSL2.

## `synt doctor`
WSL rows, warnings only, with the exact `/etc/wsl.conf` line and `wsl --shutdown`: WSL1 / WSL2 / unknown; Windows interop (the kernel's state decides, `wsl.conf` only says what the next start does, an unreadable state is reported as unknown, `enabled=false # comment` is parsed); the number of Windows directories in `PATH` (a count, never the entries); automount root and options (information only); drives mounted read-write; bubblewrap works, Landlock ABI (not used); `synt` binary on `/mnt`. Names of variables only.

## Tests
Pure (all OSes): `synthesis-platform` `wsl::tests` (detection signals, mounts, PATH scrub with an injected canonicaliser, `wsl.conf`), `synthesis-sandbox` `wsl::tests` (env scrub, mount policy: `/`, `/mnt`, `/mnt/c/Users`, `/mnt/c/Users/u`, `/mnt/wsl/x/y`, custom-mount ancestor, system dirs, protected paths) and `linux::tests::bwrap_wsl_*` (arguments: masks, hidden drives, resolv.conf, helper in front), `synthesis-config` `env::tests`, `synthesis-terminal` `wsl_mode_tests`, `synthesis-app` (`resolve_sandbox_mode`, MCP plan, doctor). Linux, real bubblewrap (`linux::tests::real`): env and `/run` inside the sandbox, hidden drive, workspace writable, readable root bound back, `mountinfo` `ro` / `rw` flags of the bound mounts when the drive is left visible. `tests/wsl.rs`: the helper's seccomp filter (AF_VSOCK denied, AF_UNIX / AF_INET work). With `SYNT_REQUIRE_BWRAP=1` (set in the Linux CI jobs, which also relax the AppArmor userns restriction) a skipped bubblewrap test is a failure. Needs real WSL2: the `#[ignore]` test `real_wsl2_sandbox_closes_interop` (`cmd.exe` unreachable, no write to `/mnt/c`, AF_VSOCK denied).
