# ADR-018: Execution isolation per attempt (worktree, sandbox, cwd scoping, locks, cleanup)

Status: Proposed (2026-11-14).
Related: ADR-005 (session-scoped workspace), ADR-015 (WSL), ADR-017, ADR-019. Specs: `docs/specs/sandbox.md`, `docs/specs/sandbox-hardening.md`, `docs/specs/workspace-context.md`.

## Context

The design requires every concurrent writable task to have its own working directory and branch, an explicit cwd that is never inherited, a documented lifecycle, and OS-level confinement because a worktree is not a security boundary.

Facts: `WorktreeManager::create(source, session_id, artifact_root, include_uncommitted)` allocates `$SYNT_HOME/worktrees/<session_id>` on branch `synthesis/<session_id>` (`synthesis-workspace/src/worktree.rs:237,283`, `synthesis-app/src/wt.rs:136`), records `GitInfo` (`worktree.rs:43`) in `sessions.git_info`, takes a repo lock that is in-process **and** cross-process (`synt-worktree.lock`, `worktree.rs:704-757`), offers `changes`, `diff`, `commit_all` (`:494`), `plan_merge` (`:524`), `execute_merge` (`:581`, merges into the original tree's current branch; no caller outside tests), and `cleanup` that refuses dirty, gitignored-bearing or unmerged work without `force` (`:628-660`). The headless run and the stdio engine default to a worktree (`docs/UNATTENDED.md:14`). Sandbox: Seatbelt (macOS), bubblewrap/Landlock (Linux), bubblewrap+seccomp (WSL), none on native Windows; egress proxy for `--network hosts` (`docs/SECURITY.md` sandbox table; `docs/specs/sandbox-hardening.md` section 1).

## Options

A. One worktree per attempt, created by the existing manager; attempt = new session; sandbox profile = the existing unattended preset.
B. One worktree per work item, reused across retries.
C. Containers per attempt.

## Decision

Option A. Containers are rejected (no new runtime dependency; sandbox backends exist).

1. **Allocation.** The orchestrator creates the attempt's session id first (UUIDv4), then the worktree with that id; the pair `(attempt_id, session_id, git_info)` is committed before the worker starts (outbox `worktree.create`, ADR-016). A crash between worktree creation and the commit is reconciled by probing `$SYNT_HOME/worktrees/<session_id>`: present and unrecorded = adopt, present and recorded = nothing, absent = redo. Design naming (a `worktrees/<task>/<attempt>` path under the pre-rename product directory) is not used: it breaks the `synt`/`SYNT_HOME` naming rules.
2. **Base.** MVP: every attempt starts from the outcome's recorded base commit (`HEAD` at contract approval, `include_uncommitted = false`, so the baseline is a clean commit and the user's dirty tree is untouched). Dependent work items that need a predecessor's changes need `create` to start at a given commit; that is an extension (PR-04) and is **not** in the MVP slice (the MVP's second item reads the first item's artifact, not its code).
3. **Subject commit.** When an attempt ends, the host runs `commit_all` (`worktree.rs:494`) in the attempt's worktree; the resulting commit id is the subject of evidence (ADR-020). The agent never commits on its own authority (git writes by the agent stay governed by `irreversible.rs`).
4. **cwd scoping: the orchestrator passes it, never a surface.** Every attempt's `WorkspaceContext` (root = the outcome's `repo_root`, cwd = the worktree subdirectory matching the contract's recorded subfolder, as `worktree.rs` already maps) is built by the orchestrator from the contract and the allocation record. A surface sends a workspace identity when it creates an outcome, resolved once to a canonical `repo_root` and stored in `outcomes`; no later request carries a path, and no code path reads the process cwd (`clippy.toml:1-6`, `synthesis-app/src/lib.rs:84`). Tests for all three entry points: CLI launch (`lib.rs:84`; the CLI `/new` test `synthesis-cli-ui/src/app/tests.rs:2958`), desktop (`apps/desktop/src/main.rs:14-22`, `tui_view/driver.rs:2077-2092` fallback and `:1616-1624`; the TUI is the only desktop surface that creates sessions today, the Super Agent must use the same protocol call), WSL (`apps/desktop/src/wsl.rs:509-520`). The desktop fallback "previous engine's root when no workspace is selected" becomes a visible refusal (plan D7). A pure `fn session_cwd(selection, ...) -> Result<PathBuf, _>` is extracted only if the audit finds a second copy of the rule.
5. **Sandbox per attempt.** Profile = unattended preset: sandbox `enforce`, network `deny` or `hosts` from user/managed settings only, wall cap, cost cap, worktree mandatory, peers off, no `--trust-project` (`docs/UNATTENDED.md:25-27`). Write root = the worktree; `.git/hooks`, `.git/config`, `.git/modules`, `.gitmodules`, `.synt`, `AGENTS.md` read-only (`synthesis-sandbox/src/lib.rs:217-226`). The orchestrator refuses to start an attempt when `enforce` cannot be satisfied (as `--unattended` refuses). Writable attempts therefore run only on macOS, Linux and WSL2, for the CLI and the desktop (TUI, Super Agent) alike; on native Windows the refusal is explicit and names WSL2 (`docs/UNATTENDED.md:17,88`), in the protocol result as well as in every surface's rendering of it.
6. **Read-only work items** (inspect, review) also get a worktree in MVP: sharing the user's checkout for reads would let a sandbox escape touch it, and the cost of a worktree is small. Revisit when a measurement says otherwise.
7. **Locks.** Within a repo, `git worktree add/remove` is already serialised by the repo lock. Outcome-level exclusive resources (design section 10) are rows in `resource_locks(resource_key PK, holder_attempt_id, fence, state)`, acquired in sorted key order inside the transaction that leases the work item. MVP has one key: `integration:<outcome_id>`; the table is added with the first merge feature, not in MVP.
8. **Cancel and cleanup.** Cancel = stop path then process-tree kill (`synthesis-terminal/src/lib.rs:493`). Cleanup runs only after the worker process has exited and, without `force`, only when `cleanup` accepts it. If it refuses (dirty, ignored files, unmerged commits) the worktree is **kept**, the attempt row records `retained_reason`, and the UI offers "open" and "discard" (discard needs a confirmation, never automatic). Retention default: until the outcome is closed, then 7 days (setting, owner decision D9). No automatic deletion of uncommitted user data.
9. **Honesty about strength.** The design's note stands: worktree is not a sandbox. Per platform the guarantee is exactly what `docs/SECURITY.md` states (macOS Weak filesystem; Linux bubblewrap Weak filesystem because `/` is bound read-only; WSL Weak; Windows none). The Outcome UI shows the attempt's sandbox backend and guarantee next to the attempt; it never says "isolated" without the qualifier.
10. **Merge is out of MVP.** The MVP ends with a branch and a patch. When merge arrives it needs a variant that merges into an outcome integration worktree, not into the user's current branch (`execute_merge`'s doc says it targets the original tree's current branch; confirm in code before building), and it is a policy action (ADR-019).

## Consequences

- Positive: isolation and recovery reuse code with tests (`synthesis-workspace/tests/workspace.rs:376,417`); attempts are inspectable as ordinary sessions.
- Negative: worktree count grows with attempts (disk, `.git/worktrees` entries); submodules are not checked out unless the user enables `synt.worktree.submodules` (`docs/UNATTENDED.md:63`) and changes inside submodules are invisible to host-side git (`:65`); Linux reads the whole filesystem until the read allow-list lands (`docs/specs/sandbox-hardening.md` section 2).
- Unverified: behaviour of ten or more concurrent worktrees on Windows/WSL; `NewSession` does not visibly validate that `cwd` lies inside `workspace_root` (not found in the code read; add a store-level check in PR-03 if absent).

## Revisit trigger

- Disk or git-metadata cost of per-attempt worktrees becomes noticeable (> 20 per repo): pool or reuse per work item (Option B).
- A native Windows sandbox (AppContainer, ADR-010 exception) exists: lift the platform exclusion.
- The Linux read allow-list ships: raise the documented guarantee.
- Remote workers: environment allocation moves behind a transport.

## Implementation notes (PR-04)

- `WorktreeManager::create_at(.., base)` starts a worktree at a full lowercase commit id of the repository (a ref name, an abbreviation, a leading `-`, a tree id are refused before git runs); `allocate_unstarted` is the idempotent form for an attempt whose worker has not started: it adopts the registered worktree on `synthesis/<session_id>`, resets a partial checkout to the base, removes an empty or `.git`-only leftover, deletes a leftover branch that has no commits of its own, and refuses everything else (another branch, other base, foreign content, a symlink at the path). It resets files, so the guard is not the caller's care: `mark_started` writes a marker in the worktree's git admin dir when the worker is launched and `allocate_unstarted` refuses a marked worktree outright; the allocation's outbox row being `done` (the effect is not re-run) and the attempt row being past `starting` (`Allocator::allocate` returns it as stored) are the other two guards. Nothing is pruned repository-wide (the user's own linked worktrees and other attempts' keep their registration); only this attempt's own stale admin entry, found by its `gitdir` file, is removed.
- `synthesis-orchestrator::Allocator` records the intent first (outbox `worktree.create`, key `worktree.create:<work item>:<ordinal>`, payload with the session id chosen up front), runs the effect (worktree, then the child session row, then `set_git_info_if_unset`; the probe is "session exists with git info and the directory exists"), then inserts the attempt row (ordinal, fence, liveness and ceilings checked by the store). Session ids are lowercase UUIDs, so two attempts never differ only by case; a recorded id that is not one is refused.
- Native Windows is refused with a message naming WSL2 (D3); a folder that is not a git repository is refused with its own message. The repo-wide lock, hardened git wrapper and pinned git dir of `worktree.rs` are reused unchanged; nothing in this change calls git outside `Git`.
- Submodules are not initialised for attempts (as for ordinary sessions, `synt.worktree.submodules` off); wiring the policy into attempts is left to PR-05 with the launch profile.
- Retention: `cleanup_attempt` never forces; a refusal (uncommitted, ignored files, unmerged commits) keeps the tree and records `attempts.retained_reason`; `retention_due(ended_at, now, days)` answers the 7-day rule, the sweeper that applies it is PR-05/PR-06.
- A finished, committed attempt's worktree is **retained until its commits are merged**: `cleanup` never removes unmerged commits, so with merge out of the MVP (D8) such worktrees stay (and `retained_reason` says why) until a person discards them. The sweeper that applies `retention_due` is not written. For an attempt whose worktree was removed, `Allocator::allocate` answers with a clear "worktree was removed" error naming the branch. The allocation also checks that the source folder is the outcome's recorded repository and that the worktree lies under the managed worktrees directory, so a tampered outbox row or session row is not followed.
- `run_outbox` and `claim_outbox` take an `OutboxFilter` (kinds, optionally one key): a dispatcher handles only the rows it has an effect for and never burns tries on others.
